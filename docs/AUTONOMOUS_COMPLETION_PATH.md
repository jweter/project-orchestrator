# Autonomous Completion Path

## Directive
Continue this plan until the four products are complete. Zero open product PRs is a build trigger, never an idle condition. The portfolio is four independent products spanning six repositories: Knowledge Engine (Core/Web/AI), Rocksmith CDLC Generator, Project Everward, and VoiceStudio Singing. Every safe unattended cycle must inspect all eligible product lanes and attempt substantive advancement without waiting for Jeremy for routine engineering, testing, repair, or verification.

This document is durable execution authority for Daedalus, the Laptop Actor, Claude specialist lanes, and future development agents. It does not grant merge, release, credential, paid-service, destructive-migration, security/privacy-boundary, or Product Reality authority beyond existing policy.

## Closed-loop operating path
OBSERVE -> SELECT -> DISPATCH -> ACQUIRE -> BUILD/REPAIR -> VERIFY -> RECORD -> LEARN -> PREVENT/REUSE -> NEXT WORK.

1. Observe live GitHub state, exact-head CI/reviews/mergeability, Laptop Actor results, worker heartbeat, and product roadmap state.
2. Reconcile terminal worker evidence before selecting more work. Never fabricate missing evidence.
3. Require five-repository Laptop Actor readiness. Missing, failed, or stale evidence is a P1 worker-repair condition.
4. Select highest-value executable work independently for Knowledge Engine, Rocksmith, and Everward. A blocked product must not block another product.
5. Use up to three conflict-free product lanes per cycle. Repairs take precedence over new slices in the affected lane.
6. Route deterministic/local work to Laptop Actor; use Claude specialist routines when measured routing warrants them; reserve humans for explicit boundaries.
7. Every job carries exact repository/base identity, governed branch, verification plan, bounded authority, and replay-safe identity.
8. Execute unattended on Azathoth where environment-dependent verification is required. Environment dependence is not human dependence.
9. Promote only exact-head verified work. Never merge red, pending, conflicted, review-blocked, missing-check, uncertain, or policy-blocked work.
10. Feed every terminal result back into planning. PASS/NO_OP releases the lane; deterministic failure becomes immediate repair; unknown fails closed.
11. Capture verified repairs/experiments as engineering episodes; fingerprint recurring failures; compile sufficiently verified episodes into reusable capabilities; inject applicable capabilities before planning; demote harmful rules.
12. Immediately select the next unfinished high-value task after a merge or successful verification. Do not stop because a PR queue became empty.

## Liveness and anti-stall invariants
- Zero open product PRs => BUILD.
- Same eligible product unadvanced for two consecutive cycles => P1 liveness defect.
- Waiting CI/preflight/worker in one lane => rotate to another eligible product.
- Never spend an entire productive cycle polishing the control plane while executable product work exists unless a P0/P1 control-plane defect prevents product execution.
- A healthy process without recent five-repository execution evidence is not portfolio-ready.
- Worker crashes/exceptions become durable repair state; they must not silently stop the loop.
- Persistent history must be bounded; telemetry is evidence, not a substitute for product advancement.

## Promotion state machine
IMPLEMENTING -> PREFLIGHT_UNVERIFIED/PREFLIGHT_GREEN -> PR_OPEN -> CI_PENDING -> GREEN -> MERGED -> PRODUCT_REALITY_PENDING/VERIFIED.

No state may be skipped by assertion. Product Reality cannot be inferred from unit tests or CI.

## Compounding learning path
Every verified episode follows OBSERVE -> DIAGNOSE -> FIX -> VERIFY -> RECORD -> PREVENT -> REUSE -> IMPROVE. Measure whether retained behavior improves Product Advancement Rate, first-pass success, failure-to-repair time, merge cycle time, repeat-failure rate, and Jeremy-required intervention. Retain only measured beneficial capabilities; demote/quarantine regressions.

## Night/idle operation
The existing persistent/recurring execution mechanisms should continue this same plan; do not create duplicate schedules. Azathoth may run bounded unattended jobs while idle. When production work is available, it outranks Engineering Gym practice. Gym work is allowed only when no higher-priority product lane is executable.

## Stop / escalation boundaries
Routine development does not require Jeremy. Escalate only for product-direction ambiguity that materially changes scope, major unauthorized architecture, paid/recurring cost, licensing, credentials, destructive migration, security/privacy boundary, release/publishing, irreversible action, or Product Reality that cannot be established automatically.

## Completion criterion
Do not declare the portfolio complete because infrastructure is mature or PR queues are empty. Completion requires each product's roadmap/acceptance criteria to be satisfied with authoritative verification, unresolved P0-P3 engineering blockers closed, required cross-repository contracts verified, and remaining Product Reality explicitly verified or presented for the smallest necessary human judgment. Until then, select and execute the next highest-value safe unfinished work.
